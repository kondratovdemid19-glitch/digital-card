# Digital card

Публичная профессиональная визитка Демида Кондратова. NestJS предоставляет GraphQL API и Apollo Sandbox, Prisma работает с PostgreSQL.

## Запуск

Нужны Docker Engine и Docker Compose. Из корня проекта:

```sh
docker compose up --build -d --wait
```

Sandbox: http://localhost:3000/graphql

Проверка доступности приложения и БД: http://localhost:3000/health

При первом старте Compose создаёт PostgreSQL, применяет сохранённую миграцию и заполняет профиль. При повторном старте миграция не применяется повторно, а seed обновляет данные того же профиля без дублей. Весь seed выполняется одной транзакцией. Данные сохраняются в Docker volume.

Если порты заняты:

```sh
PORT=18081 DB_PORT=55440 docker compose up --build -d --wait
```

Остановка с сохранением данных: `docker compose down`.

## Запрос

```graphql
query Profile {
  profile {
    name
    description
    links { label url }
    skills { name }
    experience {
      company
      position
      startDate
      endDate
      achievements
    }
    projects { name description url stack }
  }
}
```

Периоды возвращаются в формате `YYYY-MM`. У проектов без доступного публичного репозитория `url` равен `null`. Телефон, почта и служебные доступы в API не публикуются.

## Структура

- `src/profile/profile.graphql` — публичный контракт.
- `ProfileResolver` — вход GraphQL и преобразование ожидаемой ошибки отсутствующего профиля.
- `ProfileService` — получение и подготовка данных. Связи загружаются через Prisma `include`, порядок задаётся явно.
- `PrismaService` — подключение и завершение соединений с БД.
- `prisma/migrations` — миграции; `profile-data.ts` — данные; `seed.ts` — транзакционная инициализация.

API доступен только для чтения. Для одной визитки не нужны авторизация, пагинация и DataLoader. Sandbox и introspection включены намеренно для проверки задания. Внешние ошибки БД скрыты от клиента; отсутствие профиля возвращает `NOT_FOUND`.

## Проверки

Нужен Node.js 24. Тесты работают только с отдельной базой `card_test` и изменяют её данные. Основную базу `card` передать тестам нельзя.

```sh
npm ci
docker compose up -d db
docker compose exec db createdb -U card card_test
export DATABASE_URL=postgresql://card:card_local_only@localhost:55439/card_test
npm run db:migrate
npm test
npm audit
```

Команда `createdb` нужна один раз. Пароль в примере используется только для локального стенда. При его изменении через `POSTGRES_PASSWORD` нужно изменить и тестовый `DATABASE_URL`. Внешний PostgreSQL подключается через `DATABASE_URL`; для публикации следует задать отдельный пароль и использовать защищённое соединение.

Тесты проверяют вложенную выдачу, порядок и даты, повторный seed, закрытые поля и отсутствие мутаций, Sandbox, доступность БД и отсутствие утечки внутренних данных при ошибке. `npm run build` также проверяет TypeScript в строгом режиме.

Точные версии зависимостей сохранены в lock-файле. `overrides` фиксируют исправленные транзитивные зависимости. Prisma CLI оставлен в контейнере для миграций при старте; приложение запускается от пользователя `node`, с файловой системой только для чтения.

## Разработка

```sh
export DATABASE_URL=postgresql://card:card_local_only@localhost:55439/card
npm run build
npm run db:migrate
npm run db:seed
npm start
```

Для локального запуска нужно остановить контейнер приложения либо выбрать другой `PORT`. Seed хранит демонстрационные данные в коде и обновляет их при каждом старте; редактирование профиля через API в задании не предусмотрено.

При подготовке использовались AI-инструменты: реализация, тесты и ревью. Проверки выполняются на реальном PostgreSQL и в Docker; решение предоставляется с открытым описанием использованных инструментов.

## Демо на Render

`render.yaml` описывает Docker web service и PostgreSQL на плане Free. В Render нужно создать Blueprint из этого Git-репозитория и проверить выбранные планы перед подтверждением. Строка подключения передаётся из базы автоматически, пароли в Git не сохраняются. Внешний доступ к PostgreSQL закрыт; публичен только HTTP API.

Бесплатный стенд предназначен для демонстрации: web service засыпает после 15 минут без запросов, первый запрос может ждать около минуты; бесплатная БД истекает через 30 дней. Перед окончанием этого срока демо нужно пересоздать либо отдельно согласовать другой план. Опубликованный URL и дату окончания следует записать после фактического развёртывания.

Документация: https://render.com/docs/free и https://render.com/docs/blueprint-spec.
